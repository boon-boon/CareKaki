What changed

The webhook, validation, data-table loading, filtering and ranking are replaced by TypeScript functions exposed through MCP. The original workflow JSON and provider CSV are untouched. The Gemini agent and n8n memory are not embedded: your application's own model and backend own the conversation.

1 · Start locally

From the project directory, use Node.js 22 or later. The source has already been built and tested here; a fresh copy needs dependencies installed first.

npm ci
npm run build
npm run smoke

# Local application endpoint:
npm run http
# http://127.0.0.1:3000/mcp

# Or stdio (waits for a client on stdin):
npm run stdio

On this machine you can start the built HTTP entrypoint directly:

& "C:/Users/nestchao/.workbuddy-ai/binaries/node/versions/22.22.2-6/node.exe" "C:/Users/nestchao/Desktop/CareKaki/dist/http.js"

The startup command above is PowerShell syntax. Only one transport needs to run for a particular client. A stdio host launches the server itself. npm run http is for an independently running service.

2 · Connect your application

Backend integration recommended. Connect your application's MCP client to http://127.0.0.1:3000/mcp using Streamable HTTP. Initialize the protocol, list tools, and send model-selected calls through the client. MCP is JSON-RPC, not a REST endpoint that accepts bare care-request JSON.

Application backend:
  1. Connect / initialize the MCP client.
  2. Discover tools with tools/list.
  3. Supply tool names, descriptions and input schemas to your model.
  4. Dispatch tool calls through tools/call.
  5. Use structuredContent (or parse text content for legacy clients).
  6. Return results to the model and render the answer in your UI.
  7. Close the client on shutdown.

For a local subprocess host, merge the supplied mcp-client-config.json into a client configuration that uses the mcpServers format. It points to the already built server and CSV on this machine. It is a configuration example, not an installed connection. Update absolute paths when moving the project; other MCP hosts may use a different wrapper key.

4 · Clarify → confirm → search

Collect
Send partial fields to validate
Clarify
Ask returned question; merge answer
Confirm
Show normalized draft to user
Search
Send full request + confirmed:true

The server is stateless. Resend all accumulated fields on each call. A missing field returns needs_clarification; a complete but unconfirmed request returns needs_confirmation. Neither triggers a search. Reset confirmation whenever the user changes any requirement. A boolean is not proof of consent: enforce the confirmation action in your application rather than trusting a model to invent it.

{
  "name": "carekaki_search_providers",
  "arguments": {
    "location": "Petaling Jaya",
    "date": "2026-10-17",
    "start_time": "09:00",
    "duration_hours": 4,
    "required_services": ["elderly_care", "mobility_assistance"],
    "max_budget": 200,
    "preferred_language": "",
    "confirmed": true
  }
}

Production boundaries

This is an integration-ready local demo, not a production caregiver booking system.
  • No bookings, live availability sync, payments, authentication or verified real-world care records.
  • Local HTTP is unauthenticated and intentionally limited to loopback; Host/Origin guards are not authentication. Put authenticated HTTPS and authorization in front before remote access.
  • A web browser does not directly connect by default. Use your backend MCP client; add narrowly scoped CORS/Origin rules only if deliberately implementing a browser client.
  • Catalogue and diagnostic tools expose demo records. Add access controls before handling real or private provider data.
  • Exact city-name matching: “PJ” does not match “Petaling Jaya”. Search discovery includes Cheras, even though the original clarification presets did not.
  • All requested services, verified status, complete time coverage and total budget are hard filters. Language is a soft ranking preference.
  • CSV dates are fixed demo dates, primarily 17 October 2026. Future-date requests may correctly return no matches.
